# معماری — اپلیکیشن آموزش پیانو (فاز ۰)

## ۱. تصمیم‌های فنی

| موضوع | انتخاب | دلیل |
|---|---|---|
| پوسته دسکتاپ | **Electron** (فقط ویندوز در این مرحله) | Web MIDI، میکروفون و Web Audio آماده‌اند؛ UI فارسی/RTL با CSS ساده؛ نصب‌کننده با electron-builder |
| زبان | **JavaScript (ES Modules)، بدون مرحله build** | فعلاً ساده‌ترین مسیر برای اجرا و تست؛ مهاجرت به TypeScript بعداً با افزودن `tsc` و JSDoc‌های موجود ممکن است |
| نت‌نویسی | **رندرر SVG اختصاصی** (`render/notation.js`) | بدون وابستگی؛ کنترل کامل روی هایلایت نت‌ها و مکان‌نما؛ برای نت‌های مبتدی کافی است |
| صدا | Web Audio synth/sample + میزبان Native VST3 اختیاری (`native/vst-host`) | رابط پخش ثابت؛ میزبان VST3 در فرایند جداگانه و نیازمند build ویندوز |
| ورودی نوازنده | **MIDI** (مسیر اصلی) + **میکروفون** (مسیر ساده‌تر) | فاز ۲ و ۳ |
| ذخیره پیشرفت | فایل JSON در پوشه کاربر (فاز ۶) | ساده، قابل پشتیبان‌گیری |
| محتوا | فایل‌های JSON در `renderer/content` | جدا از کد؛ قابل بازبینی و تست خودکار |

Electron محتوا را از طریق پروتکل امن `app://local/` سرو می‌کند (در `electron/main.cjs`) تا `fetch` و ماژول‌ها و دسترسی MIDI/میکروفون مثل یک origin واقعی کار کنند.

## ۲. ساختار پروژه

```
electron/main.cjs        پنجره، پروتکل app://، مجوزهای MIDI/میکروفون، پل IPC میزبان VST3
electron/preload.cjs     API محدود و sandboxed برای کنترل میزبان Native
native/vst-host/         میزبان C++/JUCE برای اسکن و اجرای سازهای VST3
renderer/
  index.html, css/       رابط کاربری (RTL، فارسی)
  js/core/music.js       مدل موسیقی: نت، مدت، میزان، کلید، تایم‌لاین
  js/core/validate.js    اعتبارسنجی درس‌ها
  js/render/notation.js  رندر حامل بزرگ به SVG (+ نقشه‌ی مکان نت‌ها)
  js/render/glyphs.js    مسیر برداری کلیدها/علامت‌ها
  js/audio/synth.js      سینتی‌سایزر پیانو + مترونوم
  js/audio/transport.js  زمان‌بندی پخش (schedule خالص + اسکجولر)
  js/ui/keyboard.js      کیبورد روی صفحه
  js/app.js              کنترلر برنامه
  content/               درس‌ها (JSON)
tests/                   تست‌های خودکار (node --test)
scripts/                 سرور توسعه و ابزار رندر
```

اصل طراحی: **منطق خالص جدا از DOM**. `music.js`، `transport.js (buildSchedule)` و `notation.js` بدون مرورگر قابل تست‌اند.

## ۳. جریان داده

```
lesson.json ──► validateLesson ──► buildScore ──► { measures, timeline[] }
                                        │                 │
                                        ▼                 ▼
                                  renderScore        buildSchedule ──► ScorePlayer ──► PianoSynth
                                  (SVG + layout)          │                 │
                                        ▲                 └── onNoteOn/Off ─┘
                                        └──── هایلایت نت، مکان‌نما، کیبورد ◄──┘
```

`timeline` فهرست مرتب‌شده‌ی رویدادهاست (id، دست، ضرب شروع، مدت، نت‌ها، انگشت‌ها). همین ساختار در فاز ۲ و ۳ مرجع ارزیابی نوازنده می‌شود.

## ۴. طراحی لایه ورودی (آماده‌سازی برای فاز ۲ و ۳)

هر منبع ورودی (MIDI، میکروفون، کیبورد روی صفحه) رویدادهایی با شکل یکسان تولید می‌کند:

```js
{ type: 'noteOn' | 'noteOff', midi: 60, velocity: 0..1, time: performance.now()/1000, source: 'midi'|'mic'|'screen' }
```

موتور ارزیابی (فاز ۲) فقط این رویدادها را با `timeline` مقایسه می‌کند و به منبع کاری ندارد. بنابراین افزودن میکروفون در فاز ۳ بدون تغییر موتور ارزیابی انجام می‌شود.

محدودیت‌های شناخته‌شده‌ی میکروفون: تشخیص نت تک‌صدایی قابل اتکاست؛ آکورد و دو دست هم‌زمان دقت کمتری دارد و در فاز ۳ جداگانه و با برچسب «آزمایشی» عرضه می‌شود.

## ۴.۱ پیاده‌سازی فاز ۲

```
MIDI (js/input/midi.js) ─┐
کیبورد صفحه             ─┼─► InputHub ─► handleInput ─► صدا + کلید فشرده + Practice.handle
کلیدهای کامپیوتر        ─┘                                        │
                                                  WaitEvaluator / RhythmEvaluator (js/engine/evaluator.js, خالص)
                                                                  │
                                                  رنگ نت‌ها، مکان‌نما، راهنمای کیبورد، خلاصه‌ی نتیجه
```

- **ساعت مشترک:** زمان‌بندی نت‌های MIDI از `performance.now()` است. شروع ضرب صفر از ساعت صدا (`AudioContext`) به این ساعت تبدیل می‌شود و تأخیر خروجی صدا (`outputLatency`) به آن اضافه می‌شود تا نوازنده نسبت به چیزی که می‌شنود سنجیده شود. لغزنده‌ی «جبران تأخیر» خطای باقی‌مانده را تنظیم می‌کند.
- **بازه‌های زمانی (حالت با ضرب):** دقیق ۷۰ms، خوب ۱۴۰ms، قابل‌قبول ۲۵۰ms؛ در تمپوهای سریع حداکثر ۴۵٪ طول یک ضرب (بازه‌ها متناسب کوچک می‌شوند).
- **حالت منتظر نت:** آکورد با هر ترتیبی زده شود پذیرفته است؛ نت تکراری نادیده گرفته می‌شود؛ هر نت غلط یک اشتباه ثبت می‌کند و دقت = نت‌های بدون اشتباه در اولین تلاش ÷ کل نت‌ها.
- **حالت با ضرب:** هر نت آکورد یک «slot» جدا دارد؛ دقت = نت‌های درست ÷ (کل نت‌ها + نت‌های اضافه).
- مدت نگه‌داشتن نت (release) و پدال هنوز ارزیابی نمی‌شوند.

## ۵. تقسیم محتوای کتاب به واحدهای درسی

| واحد | محتوا | صفحات کتاب |
|---|---|---|
| ۰ | مقدمه: نشستن، شماره انگشت، کیبورد | ۴–۷ |
| ۱ | موقعیت C، حامل بزرگ، نت‌های C تا G | ۸–۱۷ |
| ۲ | آکوردها (C، G7، F) | ۱۸–۲۹ |
| ۳ | موقعیت G، پدال، آکوردهای G و D | ۳۰–۴۱ |
| ۴ | موقعیت Middle C، دینامیک، نت هشتم | ۴۲–۵۰ |
| ۵ | گسترش پنج‌انگشتی، bemol، نیم‌پرده | ۵۱–۶۱ |
| ۶ | گام و آکورد دو ماژور، بلوز | ۶۲–۶۹ |
| ۷ | گام‌های سل ماژور و فا ماژور | ۷۰–۷۹ |
| ۸ | لا مینور و ر مینور، آهنگ‌های پایانی | ۸۰–۹۵ |

هر درس از دنباله‌ای از **گام‌ها (steps)** ساخته می‌شود: درسنامه ← تمرین راهنما ← تمرین مستقل ← آزمون کوتاه (فرمت در `LESSON_FORMAT.md`).

## ۶. ریسک‌ها

1. **نت‌ها از PDF خودکار استخراج نمی‌شوند** (اسکن تصویری قدیمی). هر تمرین باید دستی به فرمت JSON بازنویسی و بازبینی شود.
2. **حق نشر:** کتاب و آهنگ‌های آن کپی‌رایت دارند. محتوای نمونه این بسته متن اورجینال + ملودی‌های دامنه‌ی عمومی است. برای انتشار تجاری، متن درس‌ها و تمرین‌ها باید اورجینال باشند.
3. **تأخیر (latency) در ویندوز:** Web Audio و Web MIDI در Chromium معمولاً کافی‌اند؛ در فاز ۷ اندازه‌گیری و در صورت نیاز کالیبراسیون تأخیر اضافه می‌شود.
4. **مجوز glyphها:** مسیر کلیدها/علامت‌ها از فونت GNU FreeSerif (GPLv3 + استثنای فونت) استخراج شده. پیش از انتشار تجاری باید با مسیرهای فونت Bravura (SIL OFL) جایگزین شود (فقط فایل `glyphs.js`).
